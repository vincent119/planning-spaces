# Import Ticket Tools 需求

## 背景

目前 Ticket 資料需要從既有 Excel 開單紀錄匯入 Opscenter。初始匯入來源為使用者本機檔案 `~/Downloads/202606-Jira開單紀錄表.xlsx`。

匯入分頁需支援動態偵測。接受 `開單記錄-MMDD` 與 `開單紀錄-MMDD` 兩種命名格式，例如 `開單記錄-0601`、`開單紀錄-011`。

初始檔案中沒有名為 `開單紀錄-061 to 0622` 的單一分頁；本次檔案實際符合匯入範圍的分頁為：

- `開單記錄-061`
- `開單記錄-068`
- `開單記錄-0615`
- `開單記錄-0622`

前兩個分頁包含 `Project` 欄位；後兩個分頁不包含 `Project` 欄位。匯入功能必須支援此欄位差異，不得因欄位缺少而產生錯誤資料。

後續檔案不可只寫死上述四個分頁；系統必須依 `開單記錄-MMDD` 或 `開單紀錄-MMDD` 命名規則自動列出可匯入分頁，並允許使用者手動勾選。

## 目標

建立一個可追溯、可預覽、可驗證的 Ticket Excel 匯入 CLI 工具，將 Excel 開單紀錄匯入既有 Ticket 主流程。

匯入完成後，系統應建立 Ticket 資料，並在 CLI 輸出每列驗證結果與匯入統計。此工具不新增匯入批次資料表。

## 範圍

本需求包含：

- 透過 `cmd/import_ticket_data` 讀取 `.xlsx` 檔案並動態讀取符合 `開單記錄-MMDD` 或 `開單紀錄-MMDD` 格式的分頁。
- 解析 Excel 欄位並轉換成 Ticket 欄位。
- 匯入前提供 CLI 預覽與逐列驗證摘要。
- 支援多分頁匯入與手動分頁選擇。
- 避免重複匯入同一張 Jira 單。
- 輸出匯入統計與錯誤報告，不建立額外匯入紀錄資料表。

本需求不包含：

- 前端 UI。
- 串接 Jira API。
- 從 Jira 自動同步狀態。
- 匯入附件。
- 自動建立不存在的主專案、事件類型或專案維運人員。
- 將 `填寫人` 對應到 `ops_user`。

本需求允許匯入時自動建立缺少的子專案與資訊來源。自動建立必須受 CLI 參數控制，預設可開啟，但預覽階段必須清楚標示哪些資料會被自動建立，避免匯入結果不可追溯。

## Excel 欄位需求

匯入工具必須支援以下來源欄位：

| Excel 欄位 | 必填 | 目標用途 |
| --- | --- | --- |
| 日期 | 是 | Ticket 建立日期或外部開單日期 |
| 已知問題 | 是 | Ticket 標題 |
| 資訊來源 | 是 | 對應 `ticket_resources` |
| 處理方式 | 否 | 合併寫入 Ticket 描述 |
| Project | 否 | 對應主專案代碼或名稱；缺少時使用目前選取主專案 |
| 填寫Jira項目選擇 | 否 | 對應子專案；留白時 `tickets.sub_project_id` 寫入 NULL |
| Jira單號 | 否 | 外部單號；有值時作為去重依據 |
| 填寫人 | 否 | 匯入來源填寫人；用於對應 `users.username` 或 `users.full_name` 後寫入 `tickets.created_by`，並保留外部文字到描述 |
| 目前進度 | 是 | 對應 Ticket 狀態 |
| 備註 | 否 | 合併寫入 Ticket 描述 |

子專案留白的匯入 Ticket，必須可在 Ticket 列表與詳情正常讀取；列表不得因關聯子專案而排除 `sub_project_id` 為 NULL 的資料。

## 狀態對應

Excel `目前進度` 必須轉換成系統 Ticket 狀態。初始規則如下：

| Excel 值 | Ticket 狀態 |
| --- | --- |
| 已完成 | resolved |
| 處理中 | in_progress |
| 未處理 | open |
| 已取消 | canceled |

無法辨識的狀態必須在預覽階段標記為錯誤，不得直接寫入。

## 事件類型與優先級

Excel 沒有明確事件類型與優先級欄位時，匯入工具必須使用可設定的預設值：

- 預設事件類型：`daily`
- 預設優先級：依事件類型設定的 `default_priority`

若預設事件類型不存在或停用，匯入預覽必須顯示阻擋錯誤。

## 資訊來源對應

Excel `資訊來源` 必須對應到目前主專案下的 `ticket_resources`。

若找不到對應資料，且 `-auto-create-resources=true`，預覽階段必須列為 `will_create_resource`，提交時自動建立 `ticket_resources` 後再建立 Ticket。

自動建立資訊來源時：

- `name` 使用 Excel `資訊來源` 原始顯示值。
- `code` 使用正規化後代碼；若後端 schema 無 `code` 欄位，則只寫入既有欄位。
- `type` 使用匯入設定預設值，初始為 `message`。
- `project_id` 使用目前主專案。
- `sub_project_id` 可依列資料帶入；若來源屬於主專案共用，則允許為空。
- `is_active` 預設為 `true`。

若 `-auto-create-resources=false`，找不到資訊來源時仍為阻擋錯誤。

## 子專案對應

Excel `填寫Jira項目選擇` 用於對應目前主專案下的 `sub_projects`。

允許使用子專案名稱或代碼比對。若找不到對應資料，且 `-auto-create-sub-projects=true`，預覽階段必須列為 `will_create_sub_project`，提交時自動建立 `sub_projects` 後再建立 Ticket。

自動建立子專案時：

- `project_id` 使用目前主專案。
- `key` 使用 Excel 值正規化後產生，必須符合後端 `sub_projects.key` 約束。
- `name` 使用 Excel 原始顯示值。
- `description` 可為空。
- `is_active` 預設為 `true`。

若 `-auto-create-sub-projects=false`，找不到子專案時仍為阻擋錯誤或依匯入設定略過。

## 填寫人處理

Excel `填寫人` 不對應 `ops_user`，也不建立 `ops_user`。

Excel `填寫人` 必須對應既有 `users` 資料，用於寫入 `tickets.created_by` 與建立活動紀錄的 `ticket_activities.actor_id`。查詢規則如下：

- 先以原始 `填寫人` 比對 `users.username` 或 `users.full_name`。
- 若原始值包含班別前綴，例如 `早-Chenmin`、`中-Eric`、`晚-Turry`，需去除前綴後再比對。
- 比對僅使用已啟用使用者，`users.is_active = TRUE`。
- 找不到對應使用者時，該列需標記為阻擋錯誤，不得默默使用 `admin` 或 CLI 操作者。
- 若來源列沒有 `填寫人`，才允許使用 `-actor-username` 對應的使用者作為 fallback。

若來源列有 `填寫人`，仍需作為外部文字保留在 Ticket 描述的匯入資訊段落中，供後續人工追溯。

## 描述合併

Excel `處理方式` 與 `備註` 不拆成獨立活動紀錄，必須合併進 Ticket 描述。

描述至少包含：

- 已知問題。
- 處理方式。
- 備註。
- 匯入資訊，例如來源分頁、Excel 列號、Jira 單號、填寫人。

## 原始檔保存

匯入時需要保存原始 Excel 檔。

原始 Excel 檔保存規則：

- 提交匯入時保存；dry-run 預覽不保存。
- 使用既有 storage 設定，不另外新增獨立檔案儲存機制。
- 保存結果必須可追溯到本次 CLI 匯入輸出。
- 原始檔不得公開下載；後續若提供 UI 查詢，必須檢查專案權限。

## 欄位映射模板

不需要支援 Excel 欄位映射模板。

匯入工具只支援本需求列出的固定欄位名稱與已知欄位差異，不實作可自定義欄位映射模板。

## 去重與冪等

匯入工具在 `Jira單號` 有值時，必須使用它作為主要去重依據。`Jira單號` 留白的列允許匯入，且不進行外部單號去重。

同一主專案內，重複匯入相同 `Jira單號` 時，系統必須依匯入模式處理：

- `insert_only`：已存在資料列標記為重複，不再寫入。
- `upsert`：更新既有 Ticket 的可更新欄位，並保留活動紀錄。

預設模式為 `insert_only`。

## 預覽與驗證

匯入前必須先產生預覽，不得上傳後直接寫入 Ticket。

預覽結果必須包含：

- 分頁名稱。
- Excel 列號。
- 原始欄位資料。
- 正規化後的 Ticket 欄位。
- 驗證狀態。
- 錯誤訊息。
- 是否會新增、更新、略過。

只要存在阻擋錯誤，預設不得提交匯入。若後續支援略過錯誤列，必須明確顯示將略過的列數。

## 權限需求

使用者必須具備目前主專案的 Ticket 建立權限，且必須能存取指定主專案。

匯入功能不可只依前端按鈕隱藏控制；後端 API 必須再次檢查權限。

## 稽核需求

系統必須透過 CLI 輸出以下操作結果：

- 匯入預覽建立。
- 匯入提交。
- 每次匯入新增、更新、略過、失敗的統計。

初始版本不新增稽核資料表，也不新增匯入批次資料表。若後續需要保存匯入歷史，再另開需求設計。

## CLI 需求

匯入工具放在 `opscenter-server/cmd/import_ticket_data`。

匯入流程：

1. 讀取 Excel 檔案。
2. 掃描符合 `開單記錄-MMDD` 或 `開單紀錄-MMDD` 格式的分頁，或使用 `-sheets` 指定分頁。
3. 正規化欄位並檢查主資料對應。
4. 預設輸出預覽與驗證摘要，不寫入資料庫。
5. 使用 `-commit` 才提交匯入。
6. 顯示新增、略過、失敗筆數與錯誤明細。

CLI 必須支援必要參數：

| 參數 | 說明 |
| --- | --- |
| `-config` | 後端設定檔路徑，預設 `config/config.yaml` |
| `-file` | Excel 檔案路徑 |
| `-project-id` | 預設主專案 ID |
| `-project-key` | 預設主專案代碼 |
| `-actor-username` | CLI 操作者與缺少 `填寫人` 時的 fallback 建立者，預設 `admin` |
| `-sheets` | 指定分頁，逗號分隔；未提供時動態偵測 |
| `-ticket-type-code` | 預設事件類型代碼，預設 `daily` |
| `-auto-create-sub-projects` | 找不到子專案時自動建立，預設 `true` |
| `-auto-create-resources` | 找不到資訊來源時自動建立，預設 `true` |
| `-resource-type` | 自動建立資訊來源時使用的類型，預設 `message` |
| `-save-source-file` | 提交時保存原始 Excel 檔，預設 `true` |
| `-commit` | 實際寫入資料庫；未提供時只預覽 |
| `-skip-invalid` | 提交時略過錯誤列 |

## 錯誤處理

匯入工具不得顯示虛假的成功狀態。

以下情境必須顯示明確錯誤：

- 檔案格式不是 `.xlsx`。
- 指定分頁不存在或沒有任何分頁符合支援的開單記錄命名格式。
- 必填欄位缺少。
- 日期格式無法解析。
- 主專案或事件類型無法對應。
- 子專案無法對應且未允許自動建立。
- 資訊來源無法對應且未允許自動建立。
- 權限不足。
- 資料庫寫入失敗。

## 安全需求

- 僅允許 `.xlsx`。
- 限制檔案大小，初始上限為 20 MB。
- 不執行 Excel 公式或巨集。
- 讀取儲存格顯示值或快取值，不允許公式造成伺服器端執行。
- 匯入錯誤訊息不得回傳敏感系統資訊。
- 原始檔案若需要保存，必須遵循附件儲存設定與存取權限。

## 驗收條件

- 可上傳 `202606-Jira開單紀錄表.xlsx` 並讀取符合 `開單記錄-MMDD` 或 `開單紀錄-MMDD` 格式的目標分頁。
- 可在預覽中看到 Excel 列號、Jira 單號、標題、資訊來源、子專案、狀態與驗證結果。
- 對於已存在的 Jira 單號，預設不重複建立 Ticket。
- 分頁缺少 `Project` 欄位時，系統使用目前選取主專案，不得匯入到錯誤主專案。
- 找不到資訊來源或子專案且未允許自動建立時，預覽階段標示錯誤，不直接寫入。
- 找不到資訊來源或子專案且允許自動建立時，預覽階段標示將自動建立，提交後必須建立對應主資料。
- 執行 `-commit` 後才會建立 Ticket。
- 執行 `-commit` 後必須保存原始 Excel 檔。
- `填寫人` 不對應 `ops_user`，但需對應既有 `users` 後寫入 `tickets.created_by`；同時保留為描述中的外部文字。
- `處理方式` 與 `備註` 合併到 Ticket 描述，不拆成獨立活動紀錄。
- 匯入結果顯示新增、更新、略過、失敗筆數。
- 未加 `-commit` 時不得寫入資料庫。
- 不新增任何新資料表；只寫入既有 Ticket、主資料、活動紀錄與附件/儲存相關資料。
