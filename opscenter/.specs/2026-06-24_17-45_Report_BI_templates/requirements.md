# Report BI Templates Requirements

## Introduction

目前 Report 範本偏向保存固定查詢條件，無法像 BI 報表一樣自定義維度、指標、分組、排序與呈現方式。此 spec 定義 Report 範本升級方向，目標是讓使用者能建立可重複執行的自定義報表，而不是只能保存少量固定欄位。

本 spec 是 `.kiro/specs/2026-06-22_11-06_Report` 的 Phase 2 / Phase 3 延伸，不修改既有內建月報 A / B / C / E 的核心語意。

## Scope

### MVP

提供有限但實用的 BI 式範本設定能力：

- 選擇資料集
- 選擇 X 軸維度
- 選擇 series 分組維度
- 選擇指標
- 選擇圖表類型
- 設定排序、Top N 與日期預設
- 預覽後儲存範本

### Out Of Scope

- 拖拉式自由版面設計器
- 任意 SQL 或自定義公式
- 跨 bounded context 任意 join
- 排程寄送
- 非同步大型報表產製

## Requirements

### 需求 1：BI 式範本定位

**使用者故事**：身為值班組長，我希望報表範本能保存完整的分析設定，之後只要調整日期即可重複使用。

#### 驗收條件

- [ ] 1.1 範本需分成查詢設定與視覺化設定，不得只保存表單欄位。
- [ ] 1.2 範本需支援未儲存預覽，使用者可在儲存前確認圖表與明細表。
- [ ] 1.3 範本執行時可覆蓋日期區間，但不得覆蓋範本內定義的資料集、維度、指標與權限範圍。
- [ ] 1.4 範本列表需顯示範本名稱、資料集、主要維度、圖表類型、建立者與更新時間。

### 需求 2：資料集與欄位白名單

**使用者故事**：身為系統管理員，我希望自定義報表只能使用被允許的欄位，避免權限繞過與 SQL injection。

#### 驗收條件

- [ ] 2.1 MVP 資料集限定為 Ticket 運維事件資料集。
- [ ] 2.2 後端需提供資料集 metadata API，回傳可用維度、指標、篩選欄位、排序欄位與支援圖表。
- [ ] 2.3 前端只能渲染 metadata API 回傳的欄位選項，不得硬編完整白名單。
- [ ] 2.4 後端需再次驗證所有 dataset、dimension、metric、filter、sort 與 chart type。
- [ ] 2.5 任意未知欄位需回傳 400，且錯誤訊息需指出欄位類型與代碼。

### 需求 3：維度、分組與指標

**使用者故事**：身為報表使用者，我希望能自己決定用人員、子專案、日期或事件類型分析資料。

#### 驗收條件

- [ ] 3.1 X 軸維度至少支援日期、人員、子專案、事件類型、狀態與優先級。
- [ ] 3.2 series 分組維度至少支援無分組、子專案、事件類型、狀態、優先級與人員。
- [ ] 3.3 指標 MVP 至少支援事件數量。
- [ ] 3.4 日期維度需支援日、週、月粒度。
- [ ] 3.5 人員維度需支援 `created_by` 與 `actor` 兩種口徑。
- [ ] 3.6 前端需避免選出無效組合，例如 X 軸與 series 使用同一個欄位時需提示或自動阻擋。

### 需求 4：篩選、排序與 Top N

**使用者故事**：身為值班組長，我希望能把常用篩選與排序保存到範本，快速產生固定口徑的月報。

#### 驗收條件

- [ ] 4.1 範本需支援狀態、事件類型、子專案、優先級、人員的固定篩選條件。
- [ ] 4.2 日期區間需支援預設值：本週、上週、本月、上月、自訂；使用者切換預設值時，起迄日期需同步更新，手動調整起迄日期時需切換為自訂。
- [ ] 4.3 排序需支援依維度名稱、日期、總量升冪與總量降冪。
- [ ] 4.4 Top N 需支援全部、Top 10、Top 20、Top 50。
- [ ] 4.5 匯出 CSV 需使用與預覽完全一致的範本設定與覆蓋日期。

### 需求 5：圖表與明細表呈現

**使用者故事**：身為報表使用者，我希望同一份範本能選擇適合的圖表與表格呈現方式。

#### 驗收條件

- [ ] 5.1 圖表類型至少支援堆疊長條、群組長條、折線與表格。
- [ ] 5.2 若選擇表格模式，仍需回傳可匯出的明細表 payload。
- [ ] 5.3 圖例需支援多列顯示，不得以分頁隱藏主要 series。
- [ ] 5.4 淺色與深色主題下，圖表文字、座標軸、格線與提示文字需跟隨 theme token。
- [ ] 5.5 明細表欄位需依範本設定產生，且與圖表資料一致。

### 需求 6：權限、審計與相容性

**使用者故事**：身為系統管理員，我希望 BI 範本仍遵守既有專案權限，且不破壞既有固定報表。

#### 驗收條件

- [ ] 6.1 範本建立、更新與刪除需沿用 Report create/update/delete 權限。
- [ ] 6.2 範本執行與匯出需沿用 Report read 權限與專案可見性。
- [ ] 6.3 範本設定變更需寫入審計日誌，包含變更前後摘要。
- [ ] 6.4 既有內建月報 A / B / C / E 不得因 BI 範本改造而改變 API 契約。
- [ ] 6.5 舊版 `report_templates.config` 需提供相容轉換或 migration 策略。

### 需求 7：報表中心頁籤分流

**使用者故事**：身為報表使用者，我希望報表預覽與範本管理分開呈現，避免範本列表壓縮報表預覽空間。

#### 驗收條件

- [ ] 7.1 報表中心需提供兩個頁籤：「報表」與「範本」。
- [ ] 7.2 「報表」頁籤只呈現報表條件、預覽、匯出與儲存範本操作，不顯示範本列表側欄。
- [ ] 7.3 「範本」頁籤需專門呈現範本列表與範本管理操作。
- [ ] 7.4 從「範本」頁籤套用範本時，需帶入範本設定並切回「報表」頁籤。
- [ ] 7.5 切換頁籤不得清空目前報表日期區間、專案範圍與未儲存的報表設定。
- [ ] 7.6 「報表」頁籤的預覽區需使用完整可用寬度，特別是每日值班執行統計矩陣不得被範本列表壓縮。
