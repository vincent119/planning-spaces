# Ticket 列表 URL 查詢狀態需求

## 文件定位

本規格針對 Ticket 列表進入詳情或編輯後返回時，日期與篩選條件被重設的問題提出新需求。既有 Ticket 列表、詳情頁、伺服器端分頁與 API 契約維持不變；本規格只新增前端 URL 查詢狀態與導覽行為。

## 背景與問題

Ticket 列表目前將日期、搜尋、篩選與分頁保存在 `ProjectTicketsPage` 的本機 state。使用者從列表進入 Ticket 詳情後，列表元件會卸載；詳情頁按「返回」重新掛載列表時，日期會再次以台北今日初始化，其他篩選與頁碼也會遺失。

例如使用者查詢 `2026-07-01` 的 Ticket，進入其中一筆詳情並完成編輯後返回，列表日期會改成返回當日，而不是原本的 `2026-07-01`。

## 使用者故事

身為 Ticket 使用者，我希望列表的搜尋、日期、篩選與分頁反映在 URL，讓我進入詳情後返回、重新整理、使用瀏覽器上一頁／下一頁或分享網址時，都能恢復相同列表結果。

## 目標

1. URL query 成為 Ticket 列表查詢狀態的可還原來源。
2. 從列表進入詳情或編輯後返回時，完整恢復原條件與頁碼。
3. 重新整理與瀏覽器歷史導覽可還原相同畫面與 API 查詢。
4. URL 可分享並重現相同列表條件。
5. 無效 query 安全回退，不造成頁面錯誤或無效 API 請求。

## 非目標

- 不修改 Ticket 列表後端 API、資料庫或伺服器端分頁契約。
- 不改變 Ticket 查詢的統計口徑、排序或權限。
- 不使用 Context、`localStorage` 或 `sessionStorage` 作為列表查詢狀態的主要來源。
- 不將使用者尚未提交的搜尋草稿立即寫入 URL。
- 不處理其他列表頁的 URL 狀態。

## 驗收條件

- [x] 1.1 URL query 至少保存搜尋關鍵字、日期起訖、狀態、優先級、事件類型、子專案、資訊來源、班別、開單人員、指派人員、頁碼與每頁筆數。
- [x] 1.2 使用者由 Ticket 列表進入詳情或編輯後返回時，所有控制項、查詢結果與 Data Grid 頁面必須恢復，不得將日期重設為今日。
- [x] 1.3 重新整理 Ticket 列表 URL 後，畫面與 API request 必須使用 URL 中相同條件。
- [x] 1.4 瀏覽器上一頁／下一頁改變 URL 時，列表控制項、Data Grid 與 TanStack Query key 必須同步還原。
- [x] 1.5 分享包含 query 的列表 URL，另一個瀏覽器分頁直接開啟後必須產生相同查詢條件。
- [x] 1.6 日期只接受 `YYYY-MM-DD`；不合法日期區間不得送出列表 API。
- [x] 1.7 不認識的狀態、優先級、非數字頁碼、不支援的每頁筆數與其他無效值必須回退安全預設值。
- [x] 1.8 會改變資料集合的搜尋或篩選條件更新時，URL 頁碼必須重設為 `1`；切換頁面或每頁筆數時只更新相關 query。
- [x] 1.9 搜尋輸入草稿在按下搜尋前不得改變已提交的 `keyword` query。
- [x] 1.10 直接開啟 Ticket 詳情而沒有可返回的列表歷史時，返回按鈕需導向該 Ticket 所屬專案的預設 Ticket 列表。
- [x] 1.11 編輯成功移除詳情頁 `edit=1` 時，不得覆蓋或遺失原列表歷史項目。

## 驗收情境

### 場景 A：返回後保留日期

假設使用者在 Ticket 列表查詢 `2026-07-01` 至 `2026-07-01`。

當使用者進入 Ticket 詳情、完成編輯並按返回。

那麼列表仍顯示 `2026-07-01` 至 `2026-07-01`，且 API 使用相同日期條件。

### 場景 B：保留完整篩選與頁碼

假設使用者已設定狀態、子專案、開單人員與指派人員，並位於第 3 頁。

當使用者進入 Ticket 詳情再返回。

那麼所有下拉選項與第 3 頁均恢復，結果不得跳回預設條件或第 1 頁。

### 場景 C：重新整理與分享

假設列表 URL 含有效日期、篩選與分頁 query。

當使用者重新整理或在另一分頁直接開啟該 URL。

那麼兩次載入都使用相同列表條件。

### 場景 D：無效 query

假設 URL 含無效日期、頁碼或不支援的 enum。

當列表解析 URL。

那麼無效值回退至安全預設值，不造成例外或送出不合法 API request。

## 影響範圍

- Ticket 列表 URL query parsing 與 serialization。
- Ticket 列表控制項、Data Grid 分頁與 TanStack Query key。
- Ticket 列表進入詳情／編輯及詳情返回 fallback。
- 對應前端單元與導覽測試。

## 驗證需求

- URL parse／serialize 單元測試。
- 日期、enum、頁碼及 page size 正規化測試。
- 返回、重新整理、分享與瀏覽器歷史導覽測試。
- `npm run typecheck`。
- `npm run build`。
- `git diff --check`。
