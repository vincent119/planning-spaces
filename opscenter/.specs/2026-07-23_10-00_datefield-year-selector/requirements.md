# DateField 年份選擇需求

## 文件定位

本 spec 定義共用 `DateField` 月曆元件新增年份選擇能力的需求。

本次只新增文件，尚未核准前不得修改前端程式碼。

原始設計稿 `../2026-06-01_10-22_oncall-ticket-system` 不在本次修改範圍。

## 背景

目前前端日期欄位使用共用自製元件 `opscenter-frontend/src/components/DateField.tsx`。

已確認現況：

- 日期欄位為唯讀，使用者不能直接輸入年份。
- 月曆浮層只有上一月與下一月。
- 中間只顯示年月文字，沒有年份選擇入口。
- 若要跨年度選日期，只能連續點擊月份切換，操作成本過高。

此元件目前被 Ticket、Jira、Report、排班週期、人員班別與國定假日相關頁面共用，因此需在共用元件層處理。

## 範圍

### 本階段包含

- `DateField` 月曆浮層新增年份選擇能力。
- 保留既有日期選取、清除、今日、上一月、下一月行為。
- 補齊月份 / 年份切換的繁體中文、簡體中文、英文 i18n。
- 補齊互動控制的 `aria-label` 與鍵盤操作可用性。
- 確認所有既有 `DateField` 使用頁面不需個別改日期邏輯。

### 本階段不包含

- 不更換整套日期套件。
- 不改 API request / response。
- 不新增日期範圍規則。
- 不改各頁預設日期計算方式。
- 不處理非 `DateField` 的原生 `TextField type="date"`。
- 不修改初始設計稿。

## 需求 1：月曆需能直接切換年份

系統需要讓使用者在月曆浮層中直接選擇年份，不需要逐月切換。

### 驗收條件

- [ ] 1.1 開啟 `DateField` 後，使用者可看到目前顯示年份。
- [ ] 1.2 使用者可直接進入年份選擇模式。
- [ ] 1.3 使用者選擇年份後，月曆需切回該年份同月份。
- [ ] 1.4 已選日期若存在，開啟月曆時仍以已選日期所在年月為預設顯示。
- [ ] 1.5 未選日期時，開啟月曆仍以台北時區今日所在年月為預設顯示。

## 需求 2：月份切換需維持直覺操作

系統需要保留既有月份切換操作，同時提供更快速的月份選擇方式。

### 驗收條件

- [ ] 2.1 上一月 / 下一月按鈕需維持既有功能。
- [ ] 2.2 使用者可在同一浮層中選擇月份。
- [ ] 2.3 選擇月份後，月曆需顯示該月份日期格。
- [ ] 2.4 月份名稱需依目前語系顯示。

## 需求 3：既有行為不得破壞

系統需要確保新增年份選擇後，不影響現有表單與查詢流程。

### 驗收條件

- [ ] 3.1 點選日期仍回傳 `YYYY-MM-DD`。
- [ ] 3.2 `清除` 仍回傳空字串並關閉月曆。
- [ ] 3.3 `今日` 仍選取台北時區今日日期並關閉月曆。
- [ ] 3.4 `disabled` 狀態不得開啟月曆。
- [ ] 3.5 `error` 與 `helperText` 顯示行為不變。
- [ ] 3.6 既有頁面的日期欄位寬度不得因新增年份選擇而明顯撐開。

## 需求 4：可及性與 i18n

系統需要讓新增控制符合基本可及性要求，且不能再出現英文未翻譯訊息。

### 驗收條件

- [ ] 4.1 年份切換入口需有繁體中文 `aria-label`。
- [ ] 4.2 月份切換入口需有繁體中文 `aria-label`。
- [ ] 4.3 年份清單或年份格需可鍵盤 focus。
- [ ] 4.4 icon-only 操作需有可讀 `aria-label`。
- [ ] 4.5 新增文案需同步 `zh-TW`、`zh-CN`、`en`。
- [ ] 4.6 `TextField` label 與 input 需維持正確關聯，避免瀏覽器可及性檢查警告。

## 需求 5：驗證

系統需要用既有前端檢查與人工操作確認 `DateField` 變更。

### 驗收條件

- [ ] 5.1 `npm run typecheck` 通過。
- [ ] 5.2 `npm run build` 通過。
- [ ] 5.3 人員班別查詢日期可直接切換年份。
- [ ] 5.4 排班週期建立日期可直接切換年份。
- [ ] 5.5 Ticket 列表日期篩選可直接切換年份。
- [ ] 5.6 Report 日期設定可直接切換年份。
