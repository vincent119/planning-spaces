## 文件定位

本 spec 接續核心 MVP 與照護細節，新增使用者主動控制的加密備份、還原與完整資料刪除，不重寫核心紀錄或加入雲端同步。

參考來源：

- 需求來源: 拆分來源 spec 的資料可攜與隱私要求
- 既有文件: 核心 spec、照護細節 spec
- 既有程式碼: 待前置規格完成後確認

## 背景

照護資料具有持續價值，裝置更換、遺失或 App 移除可能造成資料無法復原。

## 問題陳述

純本機資料若沒有安全備份與還原機制，無法承諾長期保存；不安全的備份又可能暴露敏感照護資料。

## 目標

1. 使用者可主動建立版本化且加密的離線備份。
2. 還原前完整驗證，失敗不得改動既有資料。
3. 使用者可安全刪除單筆或全部照護資料與照片。

## 非目標

1. 雲端備份、帳號、多人同步與家庭共享。
2. 公開報表、明文 JSON 與自動外傳。

## 已定決策

- 先驗證再寫入，取代前建立安全備份。
- 備份包含核心資料與私有照片。
- 加密格式與金鑰生命週期需先完成安全決策紀錄。
- 不建立 Backend Server。

## 待確認項目

- 加密演算法、金鑰保存、密碼恢復與跨平台封存格式。
- 合併衝突規則是否以 updatedAt 為唯一判斷。

## 現有行為

核心 MVP 定位為早期測試版本，沒有備份、還原或完整刪除能力。

## 新行為

使用者可建立備份、查看摘要、選擇合併或取代還原，並可完整刪除照護資料與無參照照片。

## 影響範圍

- 使用者: 需要換機、保存或刪除資料的照顧者
- 功能: 設定、備份、還原、刪除
- API / CLI: 無遠端 API；本機檔案選取與安全儲存 API
- Data / Storage: 所有本機資料表、照片、封存格式與金鑰
- 文件 / 安裝 / 發布: 隱私說明、備份版本與復原流程

## 使用情境

- 作為使用者，我想建立加密備份，以便換機後恢復照護資料。
- 作為使用者，我想確認備份內容後再還原，以免覆蓋錯誤資料。
- 作為使用者，我想完整刪除資料，以便停止使用產品時保有控制權。

## 驗收情境

### 情境：無效備份不得改動資料

- 場景：選擇損毀或無法解密的備份
- 測試：`integration_test/invalid_backup_restore_test.dart`
- 假設：裝置已有本機資料
- 當：產品驗證無效備份
- 那麼：還原停止，既有資料與照片完全不變

### 情境：取代失敗可恢復

- 場景：取代寫入中途失敗
- 測試：`integration_test/replace_restore_rollback_test.dart`
- 假設：已建立取代前安全備份
- 當：寫入過程失敗
- 那麼：產品保留或恢復原資料，不留下半套狀態

### 情境：既有行為不被破壞

- 場景：建立備份後繼續使用核心功能
- 測試：核心與照護細節回歸
- 假設：備份已成功建立
- 當：使用者新增核心紀錄與照片
- 那麼：原有 CRUD、完成數與檔案生命週期正常

## 驗收條件

1. 三個驗收情境與所有前置回歸通過。
2. 備份不得包含明文敏感資料，日誌不得輸出金鑰或內容。
3. 安全決策未確認前不得開始正式實作。

## 驗證需求

- Unit / Integration: 無效備份、rollback、合併衝突與刪除測試
- CLI / Dry-run: `flutter analyze`、`flutter test`
- 文件檢查: 安全決策、封存版本、隱私說明一致
- 回歸驗證: 核心 MVP 與照護細節全部測試

## 風險與假設

| 類型 | 內容 | 處理方式 |
|------|------|----------|
| 風險 | 錯誤加密或金鑰設計 | 實作前安全審查與決策紀錄 |
| 風險 | 還原留下半套資料 | 暫存區、交易與 rollback 測試 |
| 假設 | 使用者能安全保管備份 | UX 測試與清楚說明 |

## 摘要

- 關鍵決策: 離線加密、先驗證、取代可回復、無後端
- 待確認項目: 加密、金鑰與衝突契約
- 風險: 資料遺失與敏感資料暴露
- 下一步: 前置規格完成後先建立安全決策紀錄
