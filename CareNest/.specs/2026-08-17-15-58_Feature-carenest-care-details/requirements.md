## 文件定位

本 spec 接續 `2026-08-17-15-58_Feature-carenest-core-daily-care`，只新增餐食照片、體重、血壓與單日細節，不重寫核心完成數、餐食、高蛋白或飲水流程。

- 既有程式碼: 待核心 MVP 完成後確認

## 背景

核心 MVP 驗證每日照護確認後，家人可能需要餐點原貌與體重、血壓原始數值協助交接與回顧。

## 問題陳述

核心文字紀錄無法保存餐點視覺資訊，也無法保存體重與血壓原始量測，但新增能力不能讓產品跨入醫療判讀。

## 目標

1. 餐食可選擇附加一張本機照片與備註。
2. 可記錄並回顧體重與血壓原始數值。
3. 新功能不影響核心完成數或醫療邊界。

## 非目標

1. 圖片辨識、營養估算、健康閾值與處置建議。
2. 通知、備份、同步與 Backend Server。

## 已定決策

- 照片只存 App 私有目錄，首頁只在有照片時顯示縮圖。
- 七天摘要不顯示照片，單日明細才顯示原圖與備註。
- 體重與血壓不進入照護事項完成數。
- 圖表只呈現日期與原始數值。

## 待確認項目

- 照片來源是否只支援相機與系統選取器；待核心 MVP 後確認。
- 七天量測是否需要折線圖；需先完成低保真測試。

## 現有行為

核心規格只保存餐食文字、高蛋白與飲水，不含照片與量測。

## 新行為

餐食可附加、替換、刪除本機照片；使用者可 CRUD 體重與血壓，並在單日與七天回顧查看原始數值。

## 影響範圍

- 使用者: 需要更完整照護事實的主要照顧者
- 功能: 餐食、單日明細、量測、七天回顧
- API / CLI: 無遠端 API
- Data / Storage: MealRecord migration、私有照片、WeightRecord、BloodPressureRecord
- 文件 / 安裝 / 發布: 新增照片權限說明與 migration 驗證

## 使用情境

- 作為照顧者，我想附加餐食照片，以便家人理解餐點原貌。
- 作為照顧者，我想保存體重與血壓原始數值，以便自行回顧。

## 驗收情境

### 情境：餐食照片生命週期

- 場景：加入、替換與刪除照片
- 測試：`integration_test/meal_photo_flow_test.dart`
- 假設：既有餐食紀錄尚無照片
- 當：使用者加入、替換再刪除照片
- 那麼：畫面、資料庫路徑與私有檔案一致更新，無參照檔案被清理

### 情境：量測只呈現原始數值

- 場景：查看七天量測
- 測試：`test/features/measurements/measurement_presentation_test.dart`
- 假設：已有體重與血壓紀錄
- 當：使用者查看七天回顧
- 那麼：只看到日期與原始數值，不顯示正常、危險或處置建議

### 情境：既有行為不被破壞

- 場景：照片與量測不改變核心完成數
- 測試：核心 dashboard completion regression
- 假設：核心照護日已有完成數
- 當：新增或刪除照片與量測
- 那麼：核心完成數保持不變

## 驗收條件

1. 三個驗收情境通過，並重跑核心 MVP 全部回歸。
2. 相片權限只在使用者主動附加照片時請求。

## 驗證需求

- Unit / Integration: 上述 selector 與核心 `flutter test`
- CLI / Dry-run: `flutter analyze`、`flutter test`
- 文件檢查: 權限說明與資料 migration 一致
- 回歸驗證: 核心完成數、餐食與七天文字回顧

## 風險與假設

| 類型 | 內容 | 處理方式 |
|------|------|----------|
| 風險 | 無參照照片占用空間 | 交易成功後清理並測試 |
| 風險 | 圖表被誤解為醫療判讀 | 不畫健康區間、不使用警示詞 |
| 假設 | 照片能提升交接價值 | 使用者測試驗證 |

- 待確認項目: 照片來源與量測圖表必要性
- 風險: 檔案生命週期與醫療誤解
