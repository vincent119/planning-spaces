# 三班固定制排班與假勤管理需求

## 背景

本 spec 從 OnCall Ticket System 的「完整排班 / 假勤管理」拆出，作為獨立 bounded context。第一階段只實作三班固定制：工程師固定歸屬早班 / 中班 / 晚班，不進行早中晚輪替。系統建立排班週期時自動展開初稿，工程師再填寫例假、休假與其他假別，值班組長負責調整、確認與鎖定週期。

本功能屬 Phase 3，不作為 Ticket MVP 前置依賴。Ticket 本身不保存班別快照；未來 Ticket 依班別篩選與報表統計時，需依 Ticket 建立人 / 操作人與事件時間回查本排班資料。

## 範圍

### 本階段包含

- 三班固定制排班：早班 / 中班 / 晚班。
- 人員固定歸屬班別，支援生效日期與結束日期追溯。
- 建立排班週期並自動展開初稿。
- 工程師填寫自己的休例假與假別。
- 值班組長可調整整個週期班表。
- 早班 / 中班 / 晚班最小值班人數檢查，取代舊的同班同日休例假互斥規則。
- Global Setting 維護早中晚班共用的最小值班人數。
- Global Setting 維護現行值班班制代碼，供 Ticket 列表、Report 與排班相關班別選項共用。
- 四週 / 八週變形工時模式設定與對應檢查。
- 週期統計欄位。
- 週期確認、鎖定。
- Excel / CSV 匯出，格式對齊既有 Google Sheet。
- 排班異動審計日誌。
- 追加 task 8.8：Ticket 列表與報表依班別查詢整合，依 Ticket 建立人 / 操作人與事件時間回查當時有效班別。

### 本階段不包含

- 三班輪班制。
- 四班二輪。
- On-call 時間窗口排班。
- 人事系統匯入。
- 超出四週 / 八週變形工時基準以外的完整勞基法規則引擎。
- 請假審批流程。
- Ticket 班別篩選 / 報表整合的其他延伸能力；task 8.8 僅處理列表篩選、列表顯示與報表 `shift` 維度 / 篩選。

上述不包含項目需在後續 spec 或 deferred task 追蹤。

## 角色

- SRE 經理：可查看所有排班週期與匯出資料。
- 值班組長：可建立週期、展開初稿、調整班表、確認與鎖定週期。
- 工程師：可查看同週期班表，並編輯自己的休例假與假別。
- Admin：可維護班制、班別與人員班別歸屬。

## 名詞

- 班制：本階段固定為三班固定制。
- 班別：早班 / 中班 / 晚班，包含起訖時間與是否跨午夜。
- 核心班別：本階段指三班固定制內的早班 / 中班 / 晚班；最小值班人數規則只套用核心班別。
- 人員班別歸屬：某位工程師在指定期間固定屬於某個班別。
- 變形工時模式：排班週期與法規檢查基準，支援四週變形工時與八週變形工時。
- 排班週期：一段日期範圍，預設依變形工時模式展開四週或八週，畫面內依早 / 中 / 晚分組。
- 初稿：建立週期後由系統依人員班別歸屬自動產生的每日出勤排班；週期內每一天預設皆為 `workday`，包含週六、週日與已有國定假日標記的日期。
- 週檢查區間：以排班週期起日開始，每 7 天切成一個區間；四週週期為 4 個區間，八週週期為 8 個區間。
- 例假：每個週檢查區間必須剛好 1 天，不得 0 天，也不得同一區間排 2 天以上。
- 休假：排定休假，不等同於例假；休假額度依週期總週數計算，可由工程師在週期內移動日期，不預設綁定週六或週日。
- 國定假日資料：系統內保存的台灣特殊國定假日 / 政府行政機關辦公日曆資料，來源可為手動維護或官方開放資料同步；普通週六、週日不得因政府行事曆標示放假而被視為排班用國定假日。
- 國定假日同步：從外部官方資料來源抓取指定年度行事曆，轉換為系統內 `public_holidays` 資料，不直接修改已確認或已鎖定排班。
- 日期標記：排班矩陣日期欄需標示週六 / 週日與特殊國定假日；特殊國定假日需顯示節日名稱，是否作為每人 `public_holiday` 應排數來源需以後端 `calendar_marks.is_balance_date` 判斷，普通週末只作視覺標示，不納入 `國` 應排數。若週六同時是特殊國定假日，需顯示節日名稱；若同一假日已有補假日，原週六國定假日只作日期標記，不再納入 `國` 應排數，也不得增加 `休` 應排數。日期標記只決定 `國` 的應排數與畫面標示，不限制 `public_holiday` 實際排定日期，也不因同日排為 `statutory_holiday` 或 `day_off` 自動計入 `國` 已排數。

## 驗收條件

- [ ] 1.1 系統提供三班固定制設定，包含早班、中班、晚班三個班別，每個班別可設定名稱、起訖時間、是否跨午夜與顯示排序。
- [ ] 1.2 使用者帳號不直接保存班別；人員固定班別歸屬由獨立資料記錄，包含 `user_id`、`duty_shift_id`、`effective_from`、`effective_to`、設定人與備註。
- [ ] 1.3 同一人於同一日期不得有重疊的班別歸屬期間。
- [ ] 1.4 系統可查詢某人於任一日期的有效固定班別；若查無有效歸屬，該人不得被自動展開至排班週期。
- [ ] 1.5 工程師轉班不得覆蓋既有班別歸屬；系統必須以截止舊歸屬區間並新增新歸屬區間的方式保存歷史，避免影響歷史報表。
- [ ] 1.6 已用於 confirmed / locked 排班週期或歷史報表期間的班別歸屬不得實體刪除；若需更正，必須保留審計紀錄並使用具明確生效日期的校正流程。
- [ ] 1.7 系統需提供排班法規模式設定，支援 `4week` 四週變形工時與 `8week` 八週變形工時，作為週期預設長度、統計與確認檢查基準。
- [ ] 1.8 系統需於 Global Setting 提供 `schedule.min_staff_per_core_shift`，作為早班 / 中班 / 晚班共用的最小值班人數設定，預設值為 `1`，且不得小於 `1`。
- [ ] 1.9 系統需於 Global Setting 提供 `schedule.current_shift_group_code`，作為現行值班班制代碼，預設值為 `3shift_fixed`；Ticket 列表、Report 與排班相關班別選項不得在前端硬編碼班制，需依此設定解析出啟用中的 `shift_groups` 與其 `duty_shifts`。
- [ ] 2.1 值班組長可建立排班週期，輸入週期名稱、開始日期、結束日期與備註。
- [ ] 2.2 排班週期名稱預設格式為 `YYYYMMDD-MMDD`，例如 `20260501-0528`。
- [ ] 2.3 週期預設長度依排班法規模式決定：`4week` 預設 28 天，`8week` 預設 56 天；允許使用者指定開始與結束日期，但需標示是否符合目前模式長度。
- [ ] 2.4 建立週期時系統依日期範圍與人員有效固定班別自動展開初稿。
- [ ] 2.5 初稿對每位有效工程師與週期內每一天建立一筆排班，班別為該人的固定班別，`day_type` 預設為 `workday`，來源為 `auto`。
- [ ] 2.6 自動展開需跳過停用帳號與週期內無有效班別歸屬的人員，並回傳跳過清單。
- [ ] 2.7 初稿展開不得依週六、週日或國定假日標記自動改成 `day_off`、`statutory_holiday` 或 `public_holiday`；週末與特殊國定假日都先視為工作日，後續由工程師或值班組長排定。
- [ ] 3.1 工程師可查看同一週期內早 / 中 / 晚三組所有人的排班。
- [ ] 3.2 工程師只能編輯自己的 `day_type` 與備註。
- [ ] 3.3 值班組長可編輯週期內所有人的 `day_type` 與備註。
- [ ] 3.4 `day_type` 至少支援：`workday`、`statutory_holiday`、`day_off`、`public_holiday`、`annual`、`official`、`sick`、`personal`、`other`。
- [ ] 3.5 `day_type` 顯示文字需支援繁體中文、簡體中文、英文。
- [ ] 3.6 已確認或鎖定的週期不可再編輯排班內容。
- [ ] 4.1 同一天同一核心班別可有多人同時設定為例假、休假或其他非值班狀態，但更新後早班 / 中班 / 晚班需各自保留至少 `schedule.min_staff_per_core_shift` 位 `workday` 人員；違反時儲存失敗並回傳 409。
- [ ] 4.2 每位工程師在週期內需依目前 `4week` 或 `8week` 變形工時模式執行例假檢查；每個週檢查區間必須剛好 1 天 `statutory_holiday`，檢查結果顯示於統計欄。
- [ ] 4.3 缺例假不阻擋單格儲存，但週期確認前若仍有缺例假，系統需阻擋確認並列出缺例假的區間；若同一人同一週檢查區間已有 1 天例假，第二個 `statutory_holiday` 選項需被停用或由後端阻擋。
- [ ] 4.4 同班同日排休後若低於早中晚班最小值班人數，需阻擋單格儲存並回傳可診斷訊息；非核心班別不套用此限制。
- [ ] 4.5 排班矩陣 day type 選單需預先停用會造成早中晚班最小值班人數不足的非 `workday` 選項，並顯示停用原因。
- [ ] 4.6 `day_off` 可在週期內移動日期，不以週六日為預設休假；確認週期時需檢查每人週期內 `day_off` 已排數量與應排數量一致。
- [ ] 4.7 `public_holiday` 可在週期內移動日期，不綁定 `calendar_marks.is_balance_date`；排在一般工作日仍屬非 `workday`，必須套用核心班別最小值班人數檢查。確認週期時需檢查每人週期內 `public_holiday` 已排數量與應排數量一致。
- [ ] 5.1 週期畫面右側顯示每人統計：出勤天數、國定假數、例假數、休假數、年假、公假、病假、事假、其他。
- [ ] 5.2 週期畫面底部顯示總休假日、總例假日、總國定假。
- [ ] 5.3 週期畫面顯示每人例假檢查結果：全部正確或指定區間缺例假，區間切分需跟隨 `4week` / `8week` 模式。
- [ ] 5.4 週期畫面每人統計需顯示 `國`、`例`、`休` 的應排數、已排數與未排餘額；餘額用於提醒工程師補齊假別。
- [ ] 5.5 以 2026-09-21 至 2026-10-04 兩週週期為例，每人應排餘額基準為 `例 = 2`、`休 = 2`，若期間內有 2 個特殊國定假日，則 `國 = 2`；初稿仍全部為工作日，統計需顯示尚未排定的餘額。
- [ ] 5.6 `public_holiday.used_count`、`statutory_holiday.used_count`、`day_off.used_count` 必須分別以週期格子的 `day_type` 精準計數，對應短名 `國`、`例`、`休`；同一格只計入自身假別，不因日期標記或其他假別重疊而自動抵扣。`calendar_marks.is_balance_date` 只用於計算 `public_holiday.target_count`，週日特殊國定假日與已有補假日的原週六國定假日不納入目標數。
- [ ] 5.7 以 2026-09-17 至 2026-10-14 四週週期為例，若期間行事曆有 4 筆特殊國定假日標記，但其中 1 筆為已有補假日的原始國定假日，則每人初始未排餘額必須顯示 `國 = 3`、`例 = 4`、`休 = 4`；原始國定假日只作日期欄節日標記，不得納入 `國` 餘額，也不得讓 `休` 應排數變成 5。
- [ ] 5.8 前端所有使用者可見的國 / 例 / 休檢核不得以負數表示欠額；已排數少於應排數時顯示 `缺 N`，相等時顯示 `0`，超過時顯示 `錯`。API 的 `target_count`、`used_count`、`remaining_count` contract 與 Excel 匯出公式維持不變。
- [ ] 6.1 值班組長可確認週期；確認時需記錄確認人、確認時間與備註。
- [ ] 6.2 週期需支援 `draft`、`confirmed`、`locked` 狀態。
- [ ] 6.3 `draft` 可編輯；`confirmed` 與 `locked` 不可編輯。
- [ ] 6.4 Admin 或 SRE 經理可將 confirmed 週期鎖定為 locked。
- [ ] 7.1 每次排班新增、修改、刪除需記錄審計日誌，包含操作人、時間、異動前快照與異動後快照。
- [ ] 7.2 週期建立、確認、鎖定也需記錄系統操作審計。
- [ ] 8.1 週期支援匯出 Excel。
- [ ] 8.2 週期支援匯出 CSV。
- [ ] 8.3 匯出格式需包含日期列、星期列、人員列、每日排班格、右側統計欄、底部彙總列與組長簽名欄。
- [ ] 8.4 匯出內容以 Asia/Taipei 日期計算。
- [ ] 9.1 所有日期計算使用 Asia/Taipei。
- [ ] 9.2 API 不回傳硬編碼早中晚英文作為顯示名稱；顯示名稱來自班別主檔或 i18n。
- [ ] 9.3 未來 Ticket 查班別時使用排班 BC 查詢，不反向改動 Ticket schema。
- [ ] 9.4 未來 Ticket / Report 依班別統計時，必須以 Ticket 建立時間或活動時間查詢當時有效的人員班別歸屬，不得使用使用者目前班別回填歷史資料。
- [ ] 9.5 Ticket / Report 的班別篩選選項需限制在 `schedule.current_shift_group_code` 指定的現行值班班制內；若設定缺失或指向停用 / 不存在的班制，前端需顯示可診斷錯誤，不得退回顯示全部班別造成重覆選項。
- [x] 10.1 系統需提供國定假日資料管理 API，可依年度查詢、新增、修改、刪除手動國定假日資料。
- [x] 10.2 系統需提供國定假日同步 API，可指定年度從官方資料來源同步，並支援 preview 與 apply 兩種模式。
- [x] 10.3 國定假日官方來源第一版以 `data.gov.tw/dataset/123662` 政府行政機關辦公日曆表為主要來源，並可支援 `ruyut/TaiwanCalendar` JSON 作為備援 / 正規化來源；外部格式需透過 adapter 轉為內部模型，不得讓外部欄位直接滲入業務邏輯。
- [x] 10.4 `schedule.public_holiday_source` 需支援 `manual` 與 `api`；設定為 `manual` 時不得自動呼叫外部 API，設定為 `api` 時可由管理者手動觸發同步或由排程同步。
- [x] 10.5 外部同步需具備 idempotent 行為；同一日期重複同步不得產生重複資料，手動維護資料預設優先於 API 資料，不得被同步靜默覆蓋。
- [ ] 10.6 同步國定假日資料不得直接改動任何 `user_schedules`；建立或重新整理草稿週期也不得自動把格子改成 `public_holiday`，只能產生日期欄標記與每人 `國` 應排餘額。
- [ ] 10.7 排班矩陣需對週六 / 週日與特殊國定假日使用高對比欄底色；特殊國定假日需在日期標題直接顯示假日名稱，例如「中秋節」。若週六 / 週日同時是特殊國定假日，仍需顯示假日名稱；是否納入 `國` 餘額需依後端 `calendar_marks.is_balance_date` 判斷。日期標記不得等同於所有格子都已排定 `public_holiday` day type。
- [ ] 10.8 國定假日同步、手動新增 / 修改 / 刪除需寫入審計紀錄，包含來源、年度、差異摘要與操作者；因本規則不再自動套用到週期，不得產生自動改格審計。
