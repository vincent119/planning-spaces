# 需求文件：CareNest 多位被照顧者

## 來源

- Draft：`.specs/drafts/2026-08-19-10-27_Draft-carenest-multi-recipients/`
- Type：Feature
- Status：InProgress

## 文件定位

本功能取代核心 MVP 的「只支援一位被照顧者」限制。它延續既有本機 Drift 資料表的 `recipientId` 隔離設計，加入被照顧者的新增、切換、名稱修改與完整刪除；不重寫每日照護、量測、回顧或餐食照片功能本身。

## 背景

同一位主要照顧者可能同時照顧多位家人。現有 App 雖然每筆資料已帶有 `recipientId`，但資料庫明確拒絕第二位被照顧者，且首頁不能切換對象，導致使用者無法在同一裝置管理多人的照護狀態。

## 目標

1. 使用者可在同一裝置新增多位被照顧者，並沿用既有三步驟建立每人的照護計畫。
2. 使用者可在清楚的清單中切換目前查看與記錄的對象。
3. 使用者可修改被照顧者的稱呼。
4. 使用者可刪除被照顧者，並在二次確認後永久刪除其所有本機資料與餐食照片。
5. 切換、修改與刪除後，餐食、高蛋白、飲水、量測、趨勢與七天回顧仍嚴格只顯示目前對象資料。

## 非目標

1. 帳號、家庭邀請、雲端同步、遠端 API、Backend Server 或跨裝置共享。
2. 被照顧者資料合併、轉移、還原或封存。
3. 修改既有照護計畫欄位的介面重設計；本功能只修改被照顧者稱呼。
4. 用藥管理、醫療判讀與自動健康建議。

## 已定決策

- 所有資料只存於本機 SQLite；不會上傳或同步。
- 目前選取的被照顧者要在 App 重啟後保留。
- 新增對象沿用既有首次設定的照護計畫流程，完成後直接切換到新對象。
- 修改只涵蓋被照顧者稱呼；稱呼必填、去除前後空白、最多 100 字。
- 刪除採完整刪除：刪除設定、每日快照、餐食、高蛋白、飲水、體重、血壓與其餐食照片。
- 刪除前需顯示不可復原的影響說明，使用者必須輸入該對象稱呼完全相符才能啟用「永久刪除」。
- 刪除目前對象後，若仍有其他對象則切換到建立時間最早的其一；若已無對象則進入首次設定。

## 使用情境

- 作為主要照顧者，我想在同一支手機管理媽媽與爸爸，避免混用彼此的飲水與量測資料。
- 作為主要照顧者，我想從首頁切換正在查看的家人，在記錄前清楚知道資料會寫入誰。
- 作為主要照顧者，我想修正輸入錯誤的稱呼，不影響此人既有照護紀錄。
- 作為主要照顧者，我想永久刪除誤建或不再照顧的對象，並清楚知道歷史與照片會一起被刪除。

## 驗收情境

### 情境：新增並切換被照顧者

- 測試：`test/features/recipients/multi_recipient_controller_test.dart`、Widget 測試。
- 假設：已存在「媽媽」。
- 當：使用者新增「爸爸」並完成照護計畫。
- 那麼：首頁切換為「爸爸今天的照護狀態」，且「媽媽」既有紀錄不被修改。

### 情境：資料嚴格隔離

- 測試：`test/core/database/multi_recipient_test.dart`。
- 假設：媽媽與爸爸均有資料。
- 當：使用者切換目前對象。
- 那麼：今日首頁、量測與七天回顧只讀取目前對象的 `recipientId` 資料。

### 情境：修改稱呼

- 測試：`test/features/recipients/multi_recipient_controller_test.dart`。
- 假設：目前對象為「媽媽」且已有紀錄。
- 當：使用者將稱呼改為「外婆」。
- 那麼：首頁立即改顯示「外婆今天的照護狀態」，既有紀錄數量與內容不變。

### 情境：完整刪除被照顧者

- 測試：`test/core/database/multi_recipient_test.dart`、`test/features/recipients/multi_recipient_controller_test.dart`。
- 假設：爸爸有設定、紀錄與至少一張餐食照片。
- 當：使用者於確認頁輸入「爸爸」並執行永久刪除。
- 那麼：爸爸的所有資料列與私有餐食照片均被刪除，媽媽資料保持可讀取；若爸爸是目前對象則切換到媽媽。

### 情境：刪除最後一位對象

- 測試：`test/features/recipients/multi_recipient_controller_test.dart`。
- 假設：只剩一位被照顧者。
- 當：使用者完成永久刪除。
- 那麼：App 進入既有首次設定流程，不殘留已刪除對象的選取狀態。

## 驗收條件

1. 資料庫允許建立多位被照顧者，且舊版單一對象資料可在升級後繼續讀取。
2. 使用者可新增、切換、修改稱呼與完整刪除被照顧者。
3. 刪除流程需有不可復原說明與稱呼相符確認；不只依靠按鈕顏色表示危險。
4. `flutter analyze`、`flutter test`、`flutter build apk --debug` 與 `git diff --check` 通過。
5. 不新增網路、帳號、雲端同步或後端相依。
