## 文件定位

本 spec 由 `.specs/2026-08-17-15-43_Feature-carenest-mvp-daily-care/` 拆分而來，是目前唯一允許實作的 CareNest 規格。它只處理單一照顧者在單一裝置上的三餐、高蛋白、飲水、今日首頁與七天文字回顧，不重寫後續照片、量測、提醒、備份或家庭同步規格。

參考來源：

- 需求來源: 使用者描述的真實照護情境與已確認 UI 決策
- 既有文件: `CareNest_Product_Vision.md`、拆分來源 spec、同目錄 `design.md`
- 既有程式碼: Flutter T1 專案骨架、`lib/main.dart`、`lib/app.dart`、`test/widget_test.dart`

## 背景

主要照顧者到了晚上仍無法確認長輩是否吃過午餐、高蛋白喝了幾瓶、飲水有多少。現有資訊散落在記憶、紙本或家人對話中。第一輪需要以最小產品驗證一份可信的當日照護狀態能否消除這種不確定感。

## 問題陳述

照顧者無法在短時間內確認當日三餐、高蛋白與飲水是否已被處理，因此需要反覆詢問家人，仍可能得到不確定的答案。

## 目標

1. 使用者在 5 秒內看出今天還有哪些照護事項尚未確認。
2. 使用者在 10 秒內完成一次餐食、高蛋白或飲水紀錄。
3. 所有核心流程在沒有網路時仍可使用。
4. 使用者可回看最近 7 天的完成數與核心文字明細。

## 非目標

1. 餐食照片、體重、血壓、圖表與醫療判讀。
2. 本機提醒、通知權限、備份、還原與匯出。
3. Backend Server、遠端 API、帳號、多人同步與家庭共享。
4. 用藥管理、AI 分析、固定健康目標與營養建議。

## 已定決策

- Flutter 以 Android 開發與驗證為優先，保留 iOS 平台。
- 採 Local-first、Offline-first；SQLite 由 Drift 管理。
- 第一版只支援一位被照顧者，不建立 Backend Server。
- 首頁先顯示待確認事項，完成百分比只作輔助。
- 設定修改從下一個照護日生效；每日設定快照保護歷史完成數。
- 照護日暫以裝置當地曆日 00:00 為界。

## 待確認項目

- 正式 Android applicationId 與 iOS bundle identifier；目前暫用 `com.carenest.care_nest`。
- 低保真線框稿完成目標使用者測試後是否需要調整餐食摘要流程。

## 現有行為

目前只有可啟動的最小 Flutter App，顯示「CareNest 專案已就緒」。Android Debug APK、靜態分析與冒煙測試已通過；尚無資料庫或產品功能。

## 新行為

- 首次設定一位被照顧者、三餐時間、高蛋白與飲水目標。
- 今日首頁顯示待確認事項、完成數與核心照護摘要。
- 使用者可快速確認餐食、累加高蛋白與飲水。
- 使用者可查看最近七天完成數與單日核心文字明細。
- 設定修改只影響下一個照護日。

## 影響範圍

- 使用者: 與長輩同住或固定負責日常照護的主要家人
- 功能: 首次設定、首頁、餐食、高蛋白、飲水、七天回顧、設定修改
- API / CLI: 無遠端 API；開發驗證使用 Flutter CLI
- Data / Storage: 新增本機 SQLite／Drift 資料表與每日設定快照
- 文件 / 安裝 / 發布: 更新 README、測試與私有 spec；暫不發布商店版本

## 使用情境

- 作為主要照顧者，我想快速看見今天尚未確認的事項，以便不用再逐一詢問家人。
- 作為主要照顧者，我想記錄有沒有吃、吃了什麼、吃了多少，以便日後理解當日餐食事實。
- 作為主要照顧者，我想一鍵新增高蛋白與飲水，以便低成本維持紀錄。
- 作為主要照顧者，我想查看最近七天的照護結果，以便辨識常見缺口。

## 驗收情境

### 情境：完成首次設定

- 場景：第一次建立照護設定
- 測試：`integration_test/onboarding_flow_test.dart`
- 假設：使用者第一次開啟 App
- 當：輸入名稱、確認照護項目、餐次時間與自行設定的目標
- 那麼：進入今日首頁並顯示正確的當日待確認事項

### 情境：首頁優先顯示待確認餐次

- 場景：午餐時間已過但尚未確認
- 測試：`test/features/dashboard/pending_priority_test.dart`
- 假設：目前時間已超過午餐預計時間
- 當：使用者開啟首頁
- 那麼：午餐排在今天稍後事項之前，且只顯示中性事實文案

### 情境：快速記錄午餐

- 場景：使用者確認午餐有吃
- 測試：`integration_test/meal_quick_flow_test.dart`
- 假設：午餐尚未確認
- 當：選擇有吃、輸入「稀飯與蒸蛋」並選擇 50%
- 那麼：午餐成為已確認，首頁立即顯示摘要與更新後完成數

### 情境：一鍵新增高蛋白與飲水

- 場景：首頁快速累加
- 測試：`integration_test/quick_add_flow_test.dart`
- 假設：高蛋白為 1 / 2 瓶、飲水為 900 / 1,500 ml
- 當：點選高蛋白 `+ 1 瓶` 與飲水 `+200`
- 那麼：首頁立即顯示 2 / 2 瓶與 1,100 / 1,500 ml

### 情境：離線使用核心流程

- 場景：裝置沒有網路
- 測試：`integration_test/offline_core_flow_test.dart`
- 假設：首次設定已完成
- 當：新增核心紀錄並查看七天回顧
- 那麼：所有操作正常完成，且不要求登入或同步

### 情境：設定只影響下一個照護日

- 場景：修改既有飲水目標
- 測試：`test/features/settings/effective_next_day_test.dart`
- 假設：今天已有照護紀錄與每日快照
- 當：使用者修改飲水目標
- 那麼：今天與過去完成數不變，下一個照護日使用新目標

### 情境：既有專案骨架不被破壞

- 場景：核心功能加入後仍可啟動與編譯
- 測試：`test/widget_test.dart`
- 假設：T1 Flutter 專案骨架已完成
- 當：執行格式化、靜態分析、測試與 Android Debug APK 建置
- 那麼：全部通過，且 `android/`、`ios/` 仍保留

## 風險與假設

| 類型 | 內容 | 處理方式 |
|------|------|----------|
| 風險 | 自由文字讓餐食紀錄變慢 | 提供最多 8 筆最近摘要並進行使用者測試 |
| 風險 | 設定修改造成歷史完成數變動 | 以不可變每日設定快照隔離歷史 |
| 風險 | 第一版沒有備份 | 定位為早期測試版本，不宣稱可長期保存 |
| 假設 | 一位被照顧者足以驗證價值 | 於目標使用者測試記錄多位照護需求 |

- 風險: 自由文字紀錄成本與無備份的早期資料風險
