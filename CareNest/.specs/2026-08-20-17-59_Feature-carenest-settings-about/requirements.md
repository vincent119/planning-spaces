# 需求文件：CareNest 設定與關於頁

## 來源

- Draft: 無
- Type: Feature
- Owner: Vincent
- Status: Complete

## 文件定位

本 spec 接續使用者提出的「找個地方放關於這個產品與版本編號」，只處理設定入口、設定首頁與關於頁。既有顯示模式、文字大小、本機偏好保存、每日照護、被照顧者、量測與歷史功能不重寫。

參考來源：

- 需求來源: 2026-08-20 使用者對話確認
- 既有文件: 專案 `README.md`、`pubspec.yaml`
- 既有程式碼: `lib/features/dashboard/care_dashboard_page.dart`、`lib/features/appearance/appearance_settings_page.dart`

## 背景

目前今日首頁右上角直接提供「顯示設定」圖示，App 內沒有一般設定首頁，也沒有能讓使用者辨識 CareNest 產品定位及目前安裝版本的位置。版本已在 `pubspec.yaml` 定義為 `1.0.0+1`，但沒有顯示在 App 畫面中。

## 問題陳述

使用者無法在 App 內確認目前安裝版本，也缺少集中承載顯示設定及產品資訊的穩定入口。若把版本寫死在畫面中，後續發布時容易與實際安裝版本不一致。

## 目標

1. 將今日首頁的顯示設定入口調整為清楚的一般「設定」入口。
2. 將既有顯示模式與文字大小直接整合進設定首頁，並提供「關於 CareNest」入口。
3. 關於頁顯示產品名稱、定位文字、無廣告與本機使用承諾，以及實際安裝版本與建置編號。
4. 版本資訊由安裝套件動態取得，不在 Widget 中硬編碼。

## 非目標

1. 不實作 Google 登入、Google Drive、家庭空間、訂閱或 Backend Server。
2. 不新增隱私權政策、使用條款或客服網站的外部連結；正式網址確定後另案處理。
3. 不變更 App 的 `version:` 值，也不建立自動發布或版本遞增流程。
4. 不重新設計整個今日首頁導航。

## 已定決策

- 今日首頁使用齒輪圖示作為「設定」入口，並提供可讀的 tooltip。
- 設定首頁直接顯示「顯示模式」與「文字大小」選項，不再設置額外的顯示設定子頁。
- 既有顯示設定頁的控制邏輯遷入設定首頁，選取及保存行為維持不變。
- 「關於 CareNest」保留為設定首頁中的獨立入口，點擊後進入關於頁。
- 關於頁重用既有 CareNest 品牌圖，不新增另一套品牌圖檔。
- 關於頁顯示「讓家人知道，今天是否照顧到了。」及「本機功能不需要登入，沒有廣告。」
- 版本格式為 `版本 <version>（<buildNumber>）`，例如 `版本 1.0.0（1）`。
- 使用 `package_info_plus` 讀取安裝套件版本；不以常數複製 `pubspec.yaml` 的版本。
- 本功能不依賴網路，離線時仍可開啟。

## 待確認項目

- 無。本次不顯示公司名稱、著作權年份、聯絡信箱或尚未存在的政策連結。

## 現有行為

- 今日首頁右上角的 `display_settings_outlined` 圖示直接開啟「顯示設定」。
- 顯示設定可切換跟隨系統、淺色、深色及三種文字大小，並保存至本機。
- App 內沒有設定首頁與關於頁。
- 使用者只能從安裝資訊或 `pubspec.yaml` 得知版本。

## 新行為

- 今日首頁右上角顯示齒輪設定按鈕，tooltip 為「設定」。
- 點擊後進入「設定」首頁，可直接調整顯示模式與文字大小，並可選擇「關於 CareNest」。
- 調整顯示模式或文字大小時，既有立即更新與保存行為不變，不需再進入子頁。
- 點擊「關於 CareNest」進入獨立關於頁，顯示品牌圖、產品名稱、產品定位、無登入與無廣告承諾，以及動態版本資訊。
- 版本讀取中需有穩定佔位，不造成畫面跳動；讀取失敗時顯示可理解的文字，不顯示例外內容。

## 影響範圍

- 使用者: 所有本機使用者
- 功能: 今日首頁入口、設定首頁、顯示模式、文字大小、關於資訊
- API / CLI: 無
- Data / Storage: 無資料庫 migration；新增讀取 App 套件 metadata
- 文件 / 安裝 / 發布: `pubspec.yaml` 新增 `package_info_plus`，版本仍沿用既有發布設定

## 使用情境

- 作為 CareNest 使用者，我想在固定的位置查看產品與版本資訊，以便確認目前安裝版本並描述問題。
- 作為需要較大文字的使用者，我想在設定首頁直接調整文字大小，以減少不必要的導航步驟。

## 驗收情境

### 情境：從今日首頁進入設定

- 場景：開啟一般設定入口
- 測試：`今日首頁的設定按鈕可開啟設定首頁`
- 假設：使用者已完成首次設定並位於今日首頁
- 當：使用者點擊 tooltip 為「設定」的齒輪按鈕
- 那麼：畫面開啟標題為「設定」的設定首頁，且可看到「顯示模式」、「文字大小」與「關於 CareNest」

### 情境：查看關於與版本資訊

- 場景：顯示實際版本及建置編號
- 測試：`關於頁顯示產品資訊與版本編號`
- 假設：版本提供者回傳版本 `1.0.0`、建置編號 `1`
- 當：使用者從設定首頁開啟「關於 CareNest」
- 那麼：畫面顯示 CareNest、產品定位、無廣告承諾與「版本 1.0.0（1）」

### 情境：版本資訊讀取失敗

- 場景：套件 metadata 暫時無法取得
- 測試：`關於頁無法取得版本時顯示可理解提示`
- 假設：版本提供者回傳錯誤
- 當：關於頁完成讀取
- 那麼：頁面仍可使用且顯示「版本資訊暫時無法取得」，不得顯示技術例外或空白紅畫面

### 情境：既有行為不被破壞

- 場景：從設定首頁調整顯示偏好
- 測試：`設定首頁可直接調整既有顯示設定`
- 假設：使用者位於設定首頁
- 當：使用者直接選擇深色主題或文字大小
- 那麼：選項立即更新、偏好保存，返回後 App 維持所選外觀

## 驗收條件

1. 今日首頁的設定按鈕具有齒輪圖示及「設定」tooltip。
2. 設定首頁直接包含顯示模式與文字大小控制，並可導向關於頁；在標準、放大及特大文字下不裁切重要內容。
3. 關於頁顯示既有品牌圖、產品文案與動態版本格式。
4. 版本讀取錯誤可以恢復，不產生紅畫面。
5. 顯示模式、文字大小及本機偏好保存的既有測試持續通過。
6. 本功能不需要登入、網路或新增資料庫欄位。

## 風險與假設

| 類型 | 內容 | 處理方式 |
|------|------|----------|
| 風險 | 將既有顯示控制遷入設定首頁時造成選取或保存回歸 | 遷移既有狀態處理並保留原測試，再補設定首頁測試 |
| 風險 | 版本 metadata 在測試或平台通道初始化時失敗 | 注入可替換的版本提供者，測試成功與錯誤狀態 |
| 風險 | 特大文字造成設定列或關於頁裁切 | 使用可捲動版面與不限制單行的文字元件，加入特大字 Widget test |
| 假設 | `package_info_plus` 支援目前 Flutter、Android 與保留的 iOS 專案 | 實作前確認相容版本與平台需求 |
