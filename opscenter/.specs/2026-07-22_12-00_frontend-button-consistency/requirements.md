# 前端按鈕風格一致性需求

## 文件定位

本 spec 定義 Opscenter 後台主要功能頁的按鈕風格、操作語意與表格操作欄一致性規範。

原始設計稿 `../2026-06-01_10-22_oncall-ticket-system` 不在本次修改範圍。

## 背景

目前前端按鈕風格由各頁自行定義，造成相同語意的操作在不同頁面呈現不一致。

已確認的差異包含：

- 部分頁面使用頁面自訂漸層 `addButtonSx` / `saveButtonSx`。
- 部分頁面使用 MUI 預設 `variant="contained"`。
- 部分工具列按鈕未指定 `variant`，呈現為文字按鈕。
- 同樣是表格操作欄，有些頁面使用文字 `Button`，有些頁面使用 `IconButton + Tooltip`。
- 新增、搜尋、刷新、匯出、同步、刪除、儲存、取消等操作語意尚未集中成共用規則。

這會讓使用者在 Ticket、排班、國定假日、全域設定與排程管理之間切換時，無法穩定判斷哪一個是主操作、次操作或危險操作。

## 範圍

### 本階段包含

- 建立後台按鈕語意規範。
- 建立主要頁面共用按鈕樣式。
- 收斂表格操作欄按鈕呈現。
- 收斂工具列中的搜尋、刷新、匯出、同步、清空等操作。
- 收斂 Dialog / Form 的儲存、取消、刪除按鈕。
- 檢查繁體中文 i18n、Tooltip、aria-label 與停用狀態。
- 覆蓋下列優先頁面：
  - Ticket 列表。
  - 人員班別。
  - 排班週期。
  - 班別設定。
  - 國定假日管理。
  - 全域設定與新增 / 編輯設定。
  - 排程管理。
  - 報表中心。
  - Webhook 管理。
  - SLA 管理。
  - 班別設定新增班別入口。

### 本階段不包含

- 不重新設計整體版面。
- 不改 API 行為。
- 不改權限規則。
- 不改資料模型。
- 不修改原始初始設計稿。
- 不處理登入 / MFA 行銷式視覺背景；認證頁按鈕可在後續獨立收斂。

## 名詞

- 主操作：目前畫面最主要且會推進流程的操作，例如新增、建立、儲存、確認、套用。
- 查詢操作：依目前篩選條件觸發查詢或預覽，例如搜尋、預覽。
- 工具操作：不直接改變核心資料的輔助操作，例如刷新、匯出、同步預覽、清空日期。
- 危險操作：刪除、清除、停用等可能造成資料消失或服務狀態改變的操作。
- 表格操作欄：DataGrid 或表格右側針對單列資料的操作入口。

## 需求 1：按鈕語意必須一致

系統需要依操作語意決定按鈕樣式，而不是由單頁自行決定。

### 驗收條件

- [ ] 1.1 新增、建立、儲存、確認、套用等主操作需使用一致的主按鈕樣式。
- [ ] 1.2 搜尋、預覽等查詢操作需使用一致的 `contained` 按鈕樣式，並保留對應 icon。
- [ ] 1.3 刷新、匯出、同步預覽、清空日期等工具操作需使用一致的 `outlined` 按鈕樣式。
- [ ] 1.4 刪除、清除全部、停用等危險操作需使用 `color="error"` 或明確危險色，不得只用一般文字按鈕呈現。
- [ ] 1.5 Dialog 內取消操作需一致使用低強度按鈕；儲存 / 確認操作需使用主操作樣式。
- [ ] 1.6 停用按鈕需可辨識原因；若原因不是畫面上下文可直接理解，需提供 Tooltip 或輔助文字。

## 需求 2：共用樣式不得在頁面內重複複製

系統需要把常用按鈕樣式集中在共用元件或共用樣式，避免各頁產生微小差異。

### 驗收條件

- [ ] 2.1 不得在多個頁面重複宣告相同的 `addButtonSx`。
- [ ] 2.2 不得在多個頁面重複宣告相同的 `saveButtonSx`。
- [ ] 2.3 頁面主操作按鈕需使用共用元件或共用樣式。
- [ ] 2.4 工具列按鈕群需使用一致的間距、換行與行動版排列規則。
- [ ] 2.5 若需要保留漸層主按鈕，漸層色、hover、disabled、border radius 需集中定義。

## 需求 3：表格操作欄必須一致

系統需要讓 DataGrid / table 的單列操作欄使用一致呈現方式。

### 驗收條件

- [ ] 3.1 表格操作欄需優先使用 `IconButton + Tooltip`。
- [ ] 3.2 表格操作欄不得混用大量文字按鈕，避免欄寬過大與視覺擁擠。
- [ ] 3.3 操作順序需一致：查看、複製、編輯、執行 / 啟停、匯出、刪除。
- [ ] 3.4 刪除操作需置於操作欄最後，並使用危險色。
- [ ] 3.5 每個 icon-only 操作都需有 `Tooltip` 與 `aria-label`。
- [ ] 3.6 停用的 `IconButton` 若有停用原因，需用包裹元素保留 Tooltip。

## 需求 4：優先頁面需完成一致性調整

系統需要先處理使用者目前指出的差異頁面，再逐步收斂其他後台頁。

### 驗收條件

- [ ] 4.1 人員班別頁新增歸屬、轉班與表格操作需符合共用規範。
- [ ] 4.2 排班週期列表的建立、查看、匯出、鎖定、刪除需符合共用規範。
- [ ] 4.3 排班週期矩陣的重新整理、CSV、Excel、確認週期、鎖定週期需符合共用規範。
- [ ] 4.4 班別設定頁新增班別、編輯、啟用 / 停用與儲存需符合共用規範。
- [ ] 4.5 國定假日管理頁同步預覽、套用同步、新增假日、編輯、刪除需符合共用規範。
- [ ] 4.6 全域設定列表與新增 / 編輯設定頁需符合共用規範。
- [ ] 4.7 排程管理頁新增任務、刷新、批次刪除、清除全部與表格操作需符合共用規範。
- [ ] 4.8 Ticket 列表既有新增、搜尋、清空日期、刷新、複製、查看、編輯、刪除需作為參考基準之一，並補齊缺漏的共用化。

## 需求 5：主題切換與可讀性

系統需要確保按鈕在亮色、深色與 glass 主題中保持可讀且不突兀。

### 驗收條件

- [ ] 5.1 主按鈕文字在所有主題下需符合可讀性要求。
- [ ] 5.2 outlined 工具按鈕在深色背景上需有足夠邊框與文字對比。
- [ ] 5.3 危險色按鈕在 disabled 狀態不得被誤認為可操作。
- [ ] 5.4 按鈕文字不得超出容器；行動版需允許換行或堆疊。
- [ ] 5.5 icon-only 按鈕 hover / focus 狀態需清楚可見。

## 需求 6：驗證

系統需要用既有前端檢查與視覺檢查確認調整結果。

### 驗收條件

- [ ] 6.1 `npm run typecheck` 通過。
- [ ] 6.2 `npm run build` 通過。
- [ ] 6.3 主要頁面在深色主題截圖確認按鈕語意一致。
- [ ] 6.4 至少確認 Ticket 列表、排班週期、人員班別、國定假日管理、全域設定、排程管理六個頁面。
- [ ] 6.5 操作欄按鈕需可鍵盤 focus，且 Tooltip 文字為繁體中文。
