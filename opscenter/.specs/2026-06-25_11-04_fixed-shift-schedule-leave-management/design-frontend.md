# 三班固定制排班與假勤管理前端設計

## 路由

```text
/schedule/periods                  排班週期列表
/schedule/periods/new              建立排班週期
/schedule/periods/:id              排班週期矩陣
/schedule/assignments              人員班別歸屬管理
/schedule/shifts                   班別設定
/admin/public-holidays             國定假日管理
```

## 導覽與權限

建議新增側邊欄節點：

```text
排班假勤
  排班週期
  人員班別
  班別設定

系統管理
  國定假日管理
```

權限行為：

- Admin / op_admin：可進入系統管理底下的國定假日管理，執行手動維護與官方同步。
- Admin：可進入班別設定、人員班別歸屬管理。
- SRE 經理：可查看與匯出所有週期，可鎖定週期。
- 值班組長：可建立週期、編輯週期、確認週期、匯出；國定假日只在矩陣日期欄標示並產生餘額提醒，不會自動改格。
- 工程師：可查看週期，只能編輯自己的列。

建立週期與重新整理草稿時，初稿一律維持所有格子為工作日，不依週六、週日或國定假日資料自動改成休假、例假或國定假。不提供手動「套用國定假」按鈕；日期欄需標示週末與特殊國定假日，只有後端標示 `calendar_marks.is_balance_date = true` 的特殊國定假日納入每人 `國` 應排餘額。

日期標記不限制假別選擇。只要個人 `public_holiday` 尚有額度，週期內任意日期都可選「國」；只要目前 7 天檢查區間尚未有例假，該區間任意日期都可選「例」；「休」則只受週期總額度限制，不要求每週剛好 1 天。三種非工作日選項都需預先檢查更新後是否低於核心班別最小值班人數，「國」不得因移到一般工作日而略過此限制。

兩週週期範例：

```text
2026/09/21 - 2026/10/04
應排：例 2、休 2、國 2
初稿：所有格子先顯示早 / 中 / 晚工作日
統計：每人顯示國 / 例 / 休未排餘額，工程師排定後遞減
```

國 / 例 / 休的 Excel 匯出需保留既有公式：

```text
IF(COUNTIF(週期格子範圍, "國") > 國目標, "錯", COUNTIF(週期格子範圍, "國") - 國目標)
IF(COUNTIF(週期格子範圍, "例") > 例目標, "錯", COUNTIF(週期格子範圍, "例") - 例目標)
IF(COUNTIF(週期格子範圍, "休") > 休目標, "錯", COUNTIF(週期格子範圍, "休") - 休目標)
```

前端畫面不直接呈現上述公式產生的負數。右側統計欄、底部合計、警示訊息與前端顯示的確認失敗訊息，統一轉為：

```text
已排 < 應排：缺 N
已排 = 應排：0
已排 > 應排：錯
```

顯示順序固定為 `國 / 例 / 休`。例如 Excel 檢核值為 `0 / 0 / -1` 時，前端顯示 `國 0、例 0、休 缺 1`；Excel 匯出仍保留 `0 / 0 / -1`。前端不得直接顯示 `-1` 等負數，也不得改動 API `remaining_count = target_count - used_count` 的 contract。

四週補假驗收範例：

```text
2026/09/17 - 2026/10/14
若期間有 4 筆特殊國定假日標記，其中 1 筆為已有補假日的原始國定假日
應排：國 3、例 4、休 4
原始國定假日日期欄仍顯示節日名稱，但只影響國的應排數，不限制該日或其他日期選「國」
週期內任意格子只有短名為「國」才抵扣國；短名為「例」或「休」時只抵扣自身假別
例如 2026/10/08 不是國假餘額日，只要個人仍有國假額度且符合最小值班人數，仍可選「國」
```

### Ticket 列表班別整合

Ticket 列表篩選列新增「班別」下拉，選項來自現行值班班制設定。前端需呼叫 `GET /api/v1/schedule/current-shift-group`，使用 response 中的 `duty_shifts` 產生選項，並送出 `duty_shift_id` 給 Ticket 列表 API。

前端不得硬編碼 `3shift_fixed`，也不得呼叫未帶 `group_id` 的全部班別列表作為 Ticket 篩選選項。若目前設定缺失、指向停用班制或 API 回傳錯誤，班別下拉需 disabled，並顯示可診斷錯誤訊息，避免早班 / 中班 / 晚班因多個班制重覆出現。

Ticket 列表表格新增「班別」欄位，顯示後端回傳的 `creator_duty_shift_name`。此欄位表示 Ticket 建立者在 Ticket 建立日期的有效班別；若查無有效歸屬顯示 `-`。

### Report 設計器班別整合

Report BI 設計器 metadata 若包含 `shift` 維度，X 軸、系列與篩選皆可選用「班別」。班別篩選選項同樣來自 `GET /api/v1/schedule/current-shift-group` 的 `duty_shifts`；前端以班別名稱作為篩選值，與後端 `shift` 維度顯示值一致。

### `SchedulePeriodCreateForm`

建立週期並自動展開初稿。

欄位：

- 週期名稱，預設依日期產生 `YYYYMMDD-MMDD`
- 變形工時模式：四週 / 八週，預設讀取系統設定
- 開始日期
- 結束日期，依變形工時模式預設為 28 天或 56 天
- 備註

提交後顯示展開摘要：

- 已展開人數
- 已展開排班格數
- 被略過人員與原因

### `ScheduleMatrix`

核心排班表格。

布局：

- 橫軸：週期內日期與星期。
- 縱軸：早班 / 中班 / 晚班分組，每組內依人員排序。
- 每格：顯示 `day_type` 短名，例如 `早`、`例`、`休`、`國`、`年`。
- 右側固定統計欄：出勤、Excel 相容 `國 / 例 / 休` 檢核值、年、公、病、事、其他、四週 / 八週模式下的例假檢查。
- 底部固定彙總列：總休假日、總例假日、總國定假，並顯示全週期 Excel 相容 `國 / 例 / 休` 檢核合計。
- 早班 / 中班 / 晚班群組列顯示 `staffing_policy.min_staff_per_core_shift`，非核心班別不顯示最小值班提示。

互動：

- 點擊可編輯格子開啟 day type 選單。
- 工程師只能編輯自己的列。
- 值班組長可編輯全部列。
- confirmed / locked 狀態下所有格子唯讀。
- 若選擇非 `workday` 會讓同一日期同一核心班別低於最小值班人數，該選項需 disabled。
- disabled 的非 `workday` 選項需顯示原因：「此班別當日需至少保留 1 位值班人員」。
- 若同一人同一週檢查區間已有 1 天 `statutory_holiday`，其他日期的「例假」選項需 disabled，並顯示原因：「此週已排 1 天例假」。
- 「休假」可在週期內移動，不因日期為週六或週日自動選取。
- 「國定假」可在週期內移動，不限制於特殊國定假日標記日期；普通週末與特殊國定假日仍依 `calendar_marks` 顯示日期欄資訊，但標記只影響 `國` 應排數。
- 任意日期只有選擇「國定假」才消耗 `public_holiday` 額度；選擇「例假」或「休假」只消耗自身額度，不因 `calendar_marks.is_balance_date` 自動抵扣 `國`。
- `workday` 選項永遠可選，因為會增加值班人數。
- 儲存失敗 409 時以 inline error 或 toast 顯示衝突原因。

### `DayTypeSelect`

選項：

- 出勤 `workday`
- 例假 `statutory_holiday`
- 休假 `day_off`
- 國定假 `public_holiday`
- 年假 `annual`
- 公假 `official`
- 病假 `sick`
- 事假 `personal`
- 其他 `other`

需要 i18n 與色彩標記。

停用規則：

- 元件需讀取 Matrix response 的 `staffing_policy`。
- 元件需讀取 Matrix response 的 `leave_balances`、`columns.is_weekend` 與 `calendar_marks`；`calendar_marks` 只用於日期欄標示與說明應排數來源。
- 只對 `core_shift_codes` 內的班別套用最小值班人數。
- 以目前矩陣資料計算同一日期、同一班別的 `workday` 人數，預先判斷選擇非 `workday` 後是否低於門檻。
- 以目前矩陣資料計算同一人同一週檢查區間的 `statutory_holiday` 數量，若已達 1 天，停用其他日期的「例假」選項。
- `public_holiday` 選項不依 `calendar_marks.is_balance_date` 停用；只依個人 `public_holiday` 總額度與最小值班人數判斷。
- `public_holiday`、`statutory_holiday`、`day_off` 的預估用量分別只計算自身 day type，不做跨假別抵扣。
- 補假來源日不得改變前端顯示的 `day_off.target_count`；四週週期仍顯示 `休 4`，八週週期仍顯示 `休 8`，除非後端日後提供新的休假目標數。
- 前端停用只是使用者體驗，後端仍需在儲存與確認週期時重新檢查。

## 排班矩陣視覺規則

建議色彩：

- 出勤：依早 / 中 / 晚班使用低飽和班別色。
- 例假：藍色。
- 休假：青色。
- 國定假：紅色。
- 年假：綠色。
- 公假：紫色。
- 病假：橘色。
- 事假：黃色。
- 其他：灰色。

排班格按鈕需使用深色 / 淺色主題相容的語意色票與透明度計算背景、邊框、文字色，不可硬塞與主題突兀的固定高飽和色。出勤格保持低對比，假別格需比出勤更高對比；不可編輯但已有排班的格子仍需保留可辨識的假別色。

矩陣要支援水平捲動與固定人員欄。手機版以週為單位切換顯示，避免一次塞入完整四週或八週。

日期欄若為週六 / 週日或有 `calendar_marks` 的 `public_holiday`，整個日期欄需使用高對比欄底色區分。週末欄位由 `columns.is_weekend` 決定；特殊國定假日由 `calendar_marks` 決定。若同一日期同時是週末與特殊國定假日，日期標題需優先顯示國定假名稱，例如「中秋節」；若只是普通週末，顯示星期即可。此標記不代表該日所有格子已是 `public_holiday`，格子仍以自身 day type 顏色為準；日期欄底色需低於格子按鈕色彩層級，避免干擾排班判讀。

## 狀態

週期狀態：

- `draft`：可編輯。
- `confirmed`：不可編輯，可匯出。
- `locked`：不可編輯，可匯出，不可取消。

例假檢查：

- 全部正確：顯示成功狀態。
- 缺例假：顯示警告，列出缺漏區間。
- 例假超排：顯示錯誤，列出同一週檢查區間超過 1 天例假的人員。
- 國 / 例 / 休檢核未符合：顯示 warning，列出人員與人類可讀檢核值；例如 `國 0、例 0、休 缺 1` 或 `休 錯`，不得顯示負數。
- 檢查文案需顯示目前週期使用 `4week` 或 `8week` 模式。

## API 對接

頁面使用 React Query。

主要 query key：

```text
['schedule', 'periods', filters]
['schedule', 'period', periodId]
['schedule', 'period', periodId, 'matrix']
['schedule', 'assignments', filters]
['schedule', 'duty-shifts']
['schedule', 'public-holidays', year, filters]
['schedule', 'public-holiday-sync', year]
```

更新單格成功後 invalidate：

```text
['schedule', 'period', periodId, 'matrix']
```

建立週期成功後 invalidate：

```text
['schedule', 'periods']
```

同步國定假日 apply 成功後 invalidate：

```text
['schedule', 'public-holidays', year]
['schedule', 'period', periodId, 'matrix'] // 若目前正在檢視涵蓋該年度的週期，重新取得日期標記與餘額
```

## 前端錯誤處理

- 409 早中晚班最小值班人數不足：顯示具體日期、班別、目前值班人數與需求人數。
- 409 一週一例缺漏：確認週期時顯示缺漏人員與週次。
- 403 權限不足：顯示唯讀提示。
- 週期 confirmed / locked：編輯控制 disabled 並顯示狀態原因。

## 與歷史報表安全相關的 UI

人員轉班 UI 必須避免使用「編輯現有班別」造成誤解。建議文案：

```text
轉班會從生效日建立新的班別歸屬，過去日期仍保留原班別，不會影響歷史報表。
```

歸屬列表需以時間軸呈現歷史，讓使用者可清楚看到每段有效區間。
